# training_f021_exercises

This directory hosts the exercises for **F021** (Kubernetes training). The slides live
in the sibling `trainings` repo, `f021/slides/` (one `pages/moduleN_<topic>.md` per
module). `README.md` here says which lab of the new eight-module program uses which
material, and what is still to write.

Exercises rely on a Kubernetes cluster, either the **shared cluster** of the session
(see `shared-cluster/README.md`: `srv2052563.hstgr.cloud`, one namespace per trainee)
or one deployed locally with `kind` (https://kind.sigs.k8s.io/).

## The shared cluster

Everything about it is in `shared-cluster/`: a single-node `kind` cluster named
`training` (node `training-control-plane`) on `srv2052563.hstgr.cloud`, created by
`shared-cluster/kind.yaml` (`make create`), the same baseline as the f021bis cluster
(`../f021bis/shared-cluster/`). f021 runs on the same server *in place of* the
f021bis cluster: both claim ports 80/443/6443, so only one runs at a time, and
`make create` refuses while `training-f021bis` exists (switch steps in
`shared-cluster/README.md`, "Switching from f021bis"). Check which with `ssh
root@srv2052563.hstgr.cloud kind get clusters` before assuming the f021 one exists.
Trainees reach it the same way as f021bis, through their ttyd web console at
`https://srv2052563.hstgr.cloud/<name>/`.

- **Platform = Flux, from this repo** (path `f021/shared-cluster/clusters/hstgr`):
  Traefik + its Gateway, Linkerd, kube-prometheus-stack, Headlamp, metrics-server,
  VPA, prometheus-adapter, the room (consoles, registry) and the tenants. Change it by
  editing files and pushing, not with `kubectl`/`helm` by hand: Flux reverts drift.
  The Kustomization paths are repo-relative (`./f021/shared-cluster/...`).
- **Trainees are generic, `user1`…`userN`** (`TRAINEES` in `shared-cluster/fleet.env`).
  Never write a person's name in this repo (it is public). `tenants/` and
  `room/consoles/` are generated by `bin/render` from `templates/` and committed.
- **Secrets never in git**: `bin/gen-secrets` → `secrets/`, `secrets.yaml`, both
  git-ignored; `make secrets` applies them. The trainer's cluster-admin kubeconfig is
  `shared-cluster/kubeconfig` (`make kubeconfig`, git-ignored, context `training`).
- **Trainees are namespace `admin`** (`TRAINEES_CLUSTER_ADMIN=false`): labs must run
  within one namespace, under the `trainee` quota (no NodePort, no LoadBalancer).

## Edge: Traefik only

Traefik (HelmRelease `traefik`, values in
`shared-cluster/infrastructure/controllers/traefik-values.yaml`, the full set)
terminates TLS and gets Let's Encrypt certificates itself (resolver `le`, HTTP-01,
`acme.json` on a PVC). Nothing runs in front of it: the kind node publishes NodePorts
30080/30443 on `0.0.0.0:80/443` (`kind.yaml`), and the Service has
`externalTrafficPolicy: Local` so Traefik sees real client addresses.

Rules that are easy to break:

- **Port mappings are fixed at kind creation**: changing them means recreating the
  cluster, which loses every PVC.
- **IPv4 only.** The host names have AAAA records, but the cluster is single-stack:
  kube-proxy programs no IPv6 NodePort, so binding the mapping on `::` would DNAT to the
  node's IPv6 address and hit nothing. IPv6 needs a dual-stack rebuild.
- **`web` is the default entrypoint** (`ports.web.asDefault`). An Ingress or HTTPRoute
  with no entrypoint annotation is HTTP only. Never make `websecure` a default, nor put
  the certResolver on a router that would catch `*.nip.io` names: Traefik would ask
  Let's Encrypt for every trainee host, and nip.io's rate limit is shared with the
  internet.
- **HTTPS is opt-in** with `traefik.ingress.kubernetes.io/router.entrypoints: websecure`
  (TLS and resolver come from the entrypoint). A new HTTPS host also needs adding to
  the redirect router in `shared-cluster/infrastructure/configs/traefik-https.yaml`.
- **Proxy settings are Traefik's**: `websecure` has `readTimeout: 0` for registry
  pushes (v3 defaults to 60 s).

Namespaces: one per trainee (`user1`…), plus `consoles` (the trainees' ttyd web
consoles), `traefik`, `monitoring`, `linkerd`, `linkerd-viz`, `headlamp`, `vpa`,
`registry`, `flux-system`. Trainees run their commands, `curl` included, from their web
console, i.e. from a pod: there `127.0.0.1` is the pod itself.

## Exposing over HTTP

Anything a trainee exposes over HTTP must work on both clusters. On the shared
cluster an Ingress uses `ingressClassName: traefik` and a host with the namespace in it,
`<app>.<ns>.195.35.2.222.nip.io`, and no entrypoint annotation (HTTP only): nip.io
resolves it to the server, so it works from the console and from a browser with no
`--resolve`. HTTPS only covers the trainer's hosts (`srv2052563.hstgr.cloud` with the
consoles at `/<ns>/`, `grafana.`, `registry.`, `linkerd.`). HTTPRoutes attach to
Gateway `traefik/traefik-gateway`, same host rule. On kind the host is `<app>.<ns>.127.0.0.1.nip.io` with
`ingressClassName: nginx`. Files that carry the namespace are rendered from a `.tmpl`
with `sed "s/CHANGEME/$NS/g"` and git-ignored.
